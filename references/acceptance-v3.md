# 客户两轮反馈合并：生产验收 v3

## 已由客户反馈明确的规则（优先于旧初稿）

1. 自建多套固定模板可以，但每套须先看实物、由客户验收。不能只用一套；**客户未指定具体套数**。建议先每类两套，并非客户硬指标。
2. 同一模板版式、图层位置、字体层级、字号及颜色锁定；避免图压字、文字错位。渲染阶段使用可编辑文字图层或程序字库，不能把长中文交给图片生成模型。
3. 盘点/推荐类通常使用**透明背景的食材前景素材**。不是要求整张海报透明。去掉反复出现的“反复……及时就医”等模板化页脚；必要安全提醒只保留与问题确实相关的内容。
4. 每组**至少3张成品图片**；介绍类封面1＋营养详情1＋实拍步骤食谱3，通常5张。每道食谱要有清晰菜名、可理解的实际步骤，并与 query 情境匹配。真实照片应使用自有或已授权材料，不因去掉水印便取得版权。
5. 不得把两张“示例模板”误认为成品只需要两页。页面数量由内容需求和交付规则决定。
6. 不是堆食材与功效：每个内容块有针对 query 的用途，排除空洞重复、无意义“介绍”；必须先给读者答案，然后展开理由、选择和注意点。
7. 标题和正文以平台真实搜索者为受众，考虑搜索情境和吸引点，不捏造亲历故事。正文覆盖全部图片，按顺序书写。
8. 同一成套的详情页保持统一布局，不可在页面之间随机轮换标题和食材槽位位置；不同组可用不同经批准的模板。

## 执行顺序（不能省略）

query → 人群/场景/核心疑问 → 直接答案及必答清单 → 分类 → 选择经批准的模板 → 页面规划 → 事实核实及素材授权 → 独立文字排版和画面生成 → 合并正文 → 程序检查 → 人工审查 → 交付。

**出图前内容关卡**：写出原问题的一句话直接答案；列至少3个与 query 直接相关的实用信息点，每页必须对应信息点。信息密度不足时扩展有效信息，而非加无关页脚。

**出图后质量关卡**：像素检查文字/图片交叠、字体溢出、中文错字、背景/透明前景、素材真假、主体比例、页面重复与排序。程序无法仅凭 manifest 自动证明像素无误，必须对最终图片人工视觉复核。

## 分类范围说明

培训当前**重点教授四类**：推荐、盘点、对比、介绍；原项目还保留菜谱、测评等模板，除非用户提供该类正式培训和客户验收，不应将这些说成具有同等完整的业务规则。培训口头提过以后还会培训其他类型，数量表述不一致，不能据此认定已全部培训完成。

## 上线验收门槛

拿真实失败样本和不同长度标题跑测试；全部通过且客户确认模板后才可小批量生产。批量500组仅是扩展目标，当前包中程序**不能自动生成500组海报**。
